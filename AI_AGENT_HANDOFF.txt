QR ORGANISER - AI AGENT HANDOFF
================================

Project purpose:
This app is a QR-based organiser for physical items. Each item has a unique QR ID, a label, location, notes, and photos. The user scans a sticker/QR, opens the item, and manages the item details and images.

Core product rule:
Use a single items table only.
Do NOT create a separate item_images table.
Store all image URLs in the items row.
- image_url = the selected main/display image
- images = array of all image URLs for that item

Important architecture:
- Frontend: React + Vite
- Backend/data: Supabase
- Storage: Supabase Storage bucket named item-images
- Routing: React Router
- PWA support: vite-plugin-pwa is configured

Database schema to use:
This is the correct single-table schema for Supabase:

create table if not exists items (
  id text primary key,
  label text not null,
  location text,
  image_url text,
  images text[] not null default '{}',
  notes text,
  created_at timestamptz default now()
);

alter table items enable row level security;

create policy "public read items" on items for select using (true);
create policy "public insert items" on items for insert with check (true);
create policy "public update items" on items for update using (true);
create policy "public delete items" on items for delete using (true);

insert into storage.buckets (id, name, public)
values ('item-images', 'item-images', true)
on conflict (id) do nothing;

create policy "public read item images storage" on storage.objects
  for select using (bucket_id = 'item-images');
create policy "public upload item images storage" on storage.objects
  for insert with check (bucket_id = 'item-images');
create policy "public delete item images storage" on storage.objects
  for delete using (bucket_id = 'item-images');
create policy "public delete item images" on storage.objects
  for delete using (bucket_id = 'item-images');

IMPORTANT:
- Do NOT add an item_images table.
- Do NOT store image rows in a separate table.
- Keep the item row as the single source of truth.

Current app behavior expected:
1. Home page
- Shows a list of items
- Each card shows item label, location, id, and main image if available
- Fetches from items table with fields: id, label, location, image_url, created_at

2. New item form
- User can enter QR ID, label, location, notes
- User can upload multiple photos
- User chooses which photo is the main display image
- The app uploads files to the item-images bucket
- It saves all uploaded URLs into items.images
- It also saves the selected main image into items.image_url

3. Item detail page
- Displays the main image large
- Displays thumbnail gallery for all images
- Has buttons to set another image as the main display image
- Has an edit mode to modify fields and add more photos
- Has the ability to remove extra images from the images array
- Has delete item action that deletes storage files for item images and removes item row

4. Editing UX
- The edit view should show the current item photos in a grid
- Each image should have a button to set as main image
- Each image should have a remove button to delete that image from the array
- New images can be uploaded to add to the array
- The chosen main image should remain synchronized with image_url
